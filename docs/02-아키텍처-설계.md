## 계층별 역할

### 1. Controller Layer (컨트롤러)
- HTTP 요청을 받아서 Service 호출
- DTO로 요청/응답 처리
- 입력 검증 (`@Valid`)
- 권한 체크 (`@PreAuthorize`)

### 2. Service Layer (서비스)
- 비즈니스 로직 처리
- 트랜잭션 관리 (`@Transactional`)
- Repository를 통한 데이터 접근
- 예외 처리

### 3. Repository Layer (레포지토리)
- 데이터베이스와 직접 통신
- JPA를 통한 CRUD 작업
- 커스텀 쿼리 메서드

### 4. Security Layer (보안)
- JWT 토큰 생성/검증
- 인증 필터링
- OAuth2 처리

## 인증 흐름

### 일반 로그인 흐름
```
1. Client → POST /api/auth/login (loginId, password)
2. Controller → Service: 로그인 검증
3. Service → Repository: 사용자 조회
4. Service: 비밀번호 검증 (BCrypt)
5. Service: JWT Access Token + Refresh Token 생성
6. Service → Repository: Refresh Token DB 저장
7. Service → Client: 토큰 반환
```

### 소셜 로그인 흐름
```
1. Client → GET /oauth2/authorization/google (또는 /kakao)
2. Spring Security → OAuth2 Provider: 인증 요청
3. User: OAuth2 Provider에서 로그인
4. OAuth2 Provider → Spring Security: 인증 코드 반환
5. Spring Security → OAuth2 Provider: 액세스 토큰 요청
6. Spring Security: 사용자 정보 조회
7. OAuth2SuccessHandler: 자동 회원가입 또는 기존 사용자 조회
8. OAuth2SuccessHandler: JWT 토큰 생성
9. OAuth2SuccessHandler → Client: 토큰 반환
```

### 인증이 필요한 API 호출 흐름
```
1. Client → GET /api/user/profile
   Header: Authorization: Bearer {accessToken}
2. JwtAuthenticationFilter: 토큰 검증
3. JwtAuthenticationFilter: SecurityContext에 인증 정보 설정
4. Controller: 인증된 사용자 정보로 처리
5. Controller → Client: 응답 반환
```

### 토큰 갱신 흐름
```
1. Client → POST /api/auth/refresh
   Body: { "refreshToken": "..." }
2. Service: Refresh Token 검증 (DB 조회 + JWT 검증)
3. Service: 새로운 Access Token 생성
4. Service → Client: 새 Access Token 반환
```

## 데이터베이스 테이블 관계

```
tb_user
  ├─ userId (PK)
  ├─ loginId (이메일)
  ├─ password (BCrypt 해시)
  ├─ socialLoginYn
  ├─ provider (google, kakao 등)
  └─ providerId (소셜 로그인 ID)

tb_adminAccount
  ├─ adminId (PK)
  ├─ loginId
  ├─ password (BCrypt 해시)
  └─ level (권한 레벨)

tb_refresh_token (새로 생성)
  ├─ id (PK)
  ├─ token (Refresh Token 값)
  ├─ userType (USER 또는 ADMIN)
  ├─ userId (외래키 아님, 참조용)
  ├─ expiryDate (만료 시간)
  └─ createdAt
```

## 보안 고려사항

1. **비밀번호 해싱**: BCrypt 사용 (Spring Security 기본)
2. **JWT Secret**: 최소 256비트, 환경변수로 관리
3. **토큰 만료**: Access Token 짧게, Refresh Token 길게
4. **HTTPS**: 프로덕션 환경에서 필수
5. **CORS**: 허용된 Origin만 접근 가능하도록 설정
6. **SQL Injection 방지**: JPA 사용으로 자동 방지
7. **입력 검증**: `@Valid`와 Jakarta Validation 사용
